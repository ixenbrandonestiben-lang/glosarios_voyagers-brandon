# Glosario: Software

Este README define el formato y las normas que debe seguir cada aporte dentro del **Glosario Software**.

## Estructura del Término

Cada palabra agregada al glosario debe incluir los siguientes elementos:

1. **Término:** la palabra o concepto técnico a definir.
2. **Descripción:** explicación clara y concisa del significado del término.
3. **Ejemplo (si aplica):** un caso, fragmento de código o situación que ilustre el término. Este elemento es opcional cuando el término no lo requiera.

## Formato sugerido

```markdown
### Término

**Descripción:**
[Descripción del término]

**Ejemplo (si aplica):**
[Ejemplo o fragmento de código que ilustre el término]
```

## Ejemplo

```markdown
### API

**Descripción:**
Conjunto de reglas y protocolos que permite la comunicación entre distintos sistemas o aplicaciones de software.

**Ejemplo (si aplica):**
Una aplicación de clima consume la API de un servicio meteorológico para obtener datos actualizados de temperatura.
```

## Recordatorios

- Cada integrante debe aportar **dos palabras** para este glosario.
- Verificar que el término no esté ya registrado antes de agregarlo.
- Ambos términos de una misma persona deben incluirse en un **único commit**.
- Trabajar únicamente sobre la rama `dev/software`.
